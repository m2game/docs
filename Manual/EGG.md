# EGG.md

## UIとWorldのマウス入力競合の件

- 本質
  - Xero内部の入力管理を起点に設計するのではなく、Xeroを利用するユーザーがWorld入力を単純かつ統一された方法で実装できる使い方を先に定める
  - EGGを作るユーザーにとって、どのような公開情報がXeroに用意されているとWorld入力を楽に実装できるかを考える
  - Xero単体で入力を遮断できるだけでは解決としない
  - 現在のEGGにあるクリック、ホバー、Ray、ホイール、カメラ、キーボードの入力全体が成立することを確認してからライブラリ化する
- 問題の成立条件
  - UI Toolkitのイベント処理とUnityのInputを直接読むWorld処理は独立している
  - UIイベントの伝播を止めても、World側がInputを直接読めば入力は貫通する
  - UI上かどうかだけで処理全体を早期終了すると、World側がUpを受け取れず押下状態が残る
  - UI上で始まった押下をWorldへ移動後に再利用すると、押下途中からWorld操作が始まる
- EGGで必要な公開情報
  - 左、右、中央ボタンごとのDown、Press、Up
  - マウス位置
  - World判定用のMouseRay
  - マウスホイール量
  - Worldマウス入力を使用可能か
  - World操作中にUIへ移動した場合の強制Up
- InputManagerが保証する動作
  - UI上で開始した押下はWorldへ渡さない
  - UI上で押したままWorldへ移動しても、物理的にボタンを離すまでWorld入力を再開しない
  - World上で開始した操作中にUIへ移動した場合はUpを1回返す
  - UI上と入力遮断中はホイール量を0として返す
  - 左、右、中央ボタンを個別に管理する
  - 同じフレーム内では全ての利用側へ同じ入力結果を返す
  - キーボード入力はマウスのUI判定から独立させる
- 検証とライブラリ化の順序
  - 先に検証用コードだけで現在のEGGに必要な入力全体を再現する
  - 人間がUnity上で全項目の実動を確認する
  - 全項目が成立した後にだけXeroへ反映する
  - Xeroへ反映した後は、検証側の独自入力処理を削除してInputManagerだけで同じ確認を行う
  - EGGへ更新済みXeroを反映した後に、EGG本体を公開仕様へ移行する
- EGG側の利用方法
  - FloorPlannerInputのUpdate全体をUI判定で終了しない
  - マウスボタン処理とSceneCameraの更新は毎フレーム継続し、InputManagerが返す結果を使用する
  - ホバー判定はCanUseWorldMouseが有効な場合だけMouseRayを使用する
  - CanUseWorldMouseが無効になった場合はホバー対象を空にし、既存のホバー解除処理を通す
  - UI判定や強制Upの判断をEGG側へ重複実装しない
- UI Toolkitの入力判定
  - PanelRaycasterはポインター位置にある入力対象要素をUIとして判定する
  - 見た目が透明でも入力対象の要素はWorld入力を遮断する
  - レイアウト専用要素が画面全体を覆う場合はpicking-modeをIgnoreにする
  - Ignoreは子要素へ再帰的に適用されないため、入力透過が必要な各要素へ設定する
  - ヘッダー、ボタン、左右パネルなど実際に操作するUIは入力対象として残す
- FloorPlannerのWorld領域
  - FloorPlannerMainのRoot、Contents、中央のUISpaceが初期値のPositionだったため、中央のWorld領域もUIとして判定されていた
  - 3要素をIgnoreにすることで、中央はWorld、ヘッダーと左右パネルはUIとして判定できるようになった
- HoverWindowの点滅
  - WorldオブジェクトをホバーするとHoverWindowがカーソル位置へ表示される
  - HoverWindow自身が入力対象だったため、表示直後にマウスがUI上と判定された
  - Worldホバー解除によってHoverWindowが消えると再びWorld判定へ戻り、表示と非表示を毎フレーム繰り返していた
  - HoverWindowは情報表示専用で操作機能を持たないため、テンプレート配置、表示領域、内包ラベルをIgnoreにした
  - HoverWindowを表示したままWorldホバーを維持できることを確認した
- 確認済み
  - 検証用コードでWorldオブジェクトのホバー開始、解除、再開を確認した
  - UI上でマウスボタン入力がWorldへ渡らないことを確認した
  - World操作中にUIへ移動した場合の強制Upを確認した
  - UI上で開始した押下がWorldへ移動後も遮断されることを確認した
  - 物理的にボタンを離した後にWorld入力を再開できることを確認した
  - UI上でホイールとカメラ操作が止まることを確認した
  - UI上でもキーボード入力が動作することを確認した
  - EGG上でWorldホバーとHoverWindowの継続表示を確認した
- EGG上で残っている確認
  - UI操作でWorldオブジェクトが選択されないこと
  - World操作中にUIへ移動した場合に押下が解除されること
  - UI上で開始した押下がWorldへ移動しても操作を開始しないこと
  - UI上でホイールとカメラドラッグが反応しないこと
  - ボタンを離した後にWorld操作を再開できること
  - UI上でもキーボード入力が動作すること
