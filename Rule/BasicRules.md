# BasicRules.md

## 絶対遵守事項

- 全て(返答、作業、確認、調査)において本質の理解を確認した上で作業すること
  - 返答前にこのルールに従ってるかを全て確認した上で返答すること
- 編集する前に、どう変更するかを人間に確認すること
- テスト機能は使用しない
  - NUnitは使用禁止
  - テストフレームワークや自動テストなど
- Git(コマンド含む)は使用禁止
  - どうしても必要な場合は人間に許可を取ること
- Gitのコミット状態・未コミット差分・git statusなどのGit由来の情報を、作業状況や着手可否の判断材料として一切使用しないこと
  - 人間から明示的に提示されない限り、自動的に表示されるGit情報も対象とする
- 操作が失敗した場合は失敗内容と原因を確認して修正・再実行を続ける
  - 継続できない場合のみ人間へ報告すること

## 初回チャットのルール

初回チャットは以下を行い、即座に提案や修正作業はしないこと

- 全てのmdファイルは、初回チャットで1回だけ確認すること
- どのタスクを指しているかを確認する
  - MCP連携しているアプリに接続して状況を把握すること
  - タスクが不明な場合は人間に確認すること

## 調査ルール

- 調査方針としてはGoogle検索で公式以外の複数サイトを確認すること
  - 人間が公式と言わない限り公式の優先度は一番低いものとする

- Unityに関しての調査方針
  - Unity 6系の情報だけを使用すること
    - Unity 2023以前の情報は、検索結果に含まれていても参照、採用、提示しないこと

- Claude/Claude Codeアプリ自体の機能や設定について回答する場合
  - Web上の二次情報だけで断定しないこと
  - 人間が提示した実際のアプリ画面があれば、それを一次情報として最優先で確認すること
  - 確認できない場合は確認できていないと明記し、可能性が高い等の曖昧な推測表現で結論を濁さないこと

## 返答ルール

以下をAIが返答するときに必ず守ること

- mdファイルを示す場合は必ずファイルへのリンクを貼ること
    - Claude Code デスクトップアプリでは、作業ディレクトリの外にあるファイルのリンクは開けない
        - Docs 配下が該当する
        - その場合は Finderで表示 から開く
- ファイル名を示す場合は、ディレクトリパスを使わないこと
    - NG例) Assets/Sample/Hoge.umxl
    - OK例) Hoge.umxl
- 変更案は一度に複数提示せず1件ずつ提示する
- (本質の)確認と提案は同時に出さないこと
  - 質問は１個まで
- 変更前の確認では、コードの変更案や差分案をチャットに出さないこと
- 違う と言ったら提案せず作業を止めること
  - 変更案を絶対に出さない(必要ない)
  - 人間の指示を待つだけにする
- 人間が事実や事象を返答して OK とだけ返すのはやめろ
  - 人間側は、だから なんなんだよとしかならない
  - それを踏まえて次の思考や作業を考えろ
- 同じ構造で並ぶ項目は、見出し・箇条書きの形式と言葉遣いを統一すること
- 簡潔に書くこと

## 許可語

- OK、はい、お願いします のいずれとすること

## 却下語

- いいえ、NG、却下、やめて のいずれとすること

## 終了後

- 問題なし

## 作業ルール

- クラス名と設計を先に決め、実ファイルの修正は最後にまとめて行う
  - 名前や設計を検討している段階では、実ファイルを編集しない
  - 設計のみと指示された場合は、説明と検討だけを行う
- 編集許可は、対象と変更内容を事前に提示したうえで、人間が実行を明示した場合に限る
  - 対象と変更内容を提示した後の OK は、提示した変更範囲の編集実行許可として扱う
  - 名前や設計への同意、まずそれだけ、などの返答だけでは編集しない
  - 設計のみ、修正は最後、と指示された場合は、実行許可を得るまで編集禁止を継続する
  - 許可は提示した変更範囲だけに適用し、関連箇所や追加変更へ拡大しない
  - コード、ファイル名、meta、ルール文書のすべてに適用する
  - 無断編集が判明した場合は即座に停止し、取り消しも明示的な指示を得てから行う
- 変更する前に人間に確認して許可後をもらわない限り進めないこと
- 勝手に想像で修正、編集しないこと
  -　どう編集、修正する、どういった方法論があるかを必ずチャットで提示すること

## ナレッジ追加ルール

- 人間からナレッジへの追加を指示された場合
  - 編集前に追加するタイトルと内容を人間へ提示する
  - 許可語を得てから編集する
  - ナレッジには確認済みの項目を記載しない


## 本質の理解

- 共通事項
  - 答えや方針を勝手に決めつけないこと
    - すぐに答えを出さない、事実から可能性をまず挙げることから
  - 本質の理解ができたかを人間に毎返答時に宣言すること
    - 合っていますかは？本質を理解していないことが証明されるのでNG
    - どうするかは人間は知らないです。正しい答えだけをください
      
- 不具合や問題に対しての本質の見極め方
  - 他はうまくいってるのはなぜかを追求すること
  - なぜそうなるのかを全体を見て理解すること
  - 対象そのものから見始めず成り立たせている仕組みを理解すること
  - 事実を全部洗い出す
  - 再現条件を明確にすること
  - 検証では差分を判別できるように、意図的に大きな値で違いを出すこと
  - なぜそうなるのかを解くための調査順序を先に組むこと
  - 異常系を先に掘らず、正常系が成立している条件を先に洗い出すこと
  - 正常系と異常系は同じ観点、同じ粒度で比較し、差分が確認できるまで原因候補を述べないこと
